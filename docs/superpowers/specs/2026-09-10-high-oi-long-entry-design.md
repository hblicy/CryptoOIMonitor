# 高 OI/MC 开多规则调整设计

日期：2026-09-10

## 背景

当前交易状态机把 `OI / 市值 > 200%` 视为开多上限：无仓位候选直接归入“停止开多”，活动 `long` 状态会转为 `no_add`，`no_add` 也不能恢复做多。

新的业务判断是：高于 200% 的 OI/MC 更支持开多，不应单独触发停止开多或阻止恢复。200% 阈值仍可用于页面风险分区，但不再参与交易准入。

## 目标行为

- 开多和恢复做多只要求 `OI / 市值 > 90%`，不设 OI/MC 上限。
- `OI / 市值 > 200%` 时用与 `90% < OI / 市值 <= 200%` 完全相同的其他确认条件：
  - 当前快照完整；
  - 存在约 15 分钟前的完整参考快照；
  - 价格校正后的聚合 OI 增长；
  - 当根已收盘 15m K 线上穿 EMA200，且当前收盘仍高于 EMA200；
  - EMA200 向上；
  - 当前成交额严格高于前 20 根均量的 2 倍；
  - RSI(14) 回升；
  - 如处于退出冷却状态，冷却已经结束且突破发生在冷却结束后。
- 高 OI/MC 本身不产生 `STOP_LONG`，不执行 `long -> no_add`。
- 此前处于 `no_add` 的状态，在其他恢复条件全部满足后可以发送 `RESUME_LONG` 并回到 `long`。
- ATR 止损、移动保护、EMA 缓冲跌破和连续两根收盘低于 EMA200 等独立退出条件保持不变；满足时仍优先产生 `EXIT_LONG`。

## 保留行为

- `OI / 市值 <= 90%` 仍阻止开多，并可让活动 `long` 转为 `no_add`。
- 快照不完整、比较数据缺失、K 线失败和回放缺口时的保守状态处理保持不变。
- `AMBUSH_OI_TO_MARKET_CAP_RATIO = 2` 和 `high_risk` 展示分区保留，用于页面标识，不再作为交易条件。
- 系统只发送信号，不自动下单，不写入杠杆、资金或网格参数。

## 实现边界

### 交易状态机

`trade_dispatch.py` 中的 OI/MC 交易原因只保留 `<= 90%`。候选筛选和 K 线加载不再排除无活动状态的 `> 200%` 标的，也不再为其生成无需 K 线的“停止开多”结果。

活动状态仍先执行完整的 K 线回放和强制退出判断；没有强制退出时，`> 200%` 不再改变状态。`no_add` 和冷却结束后的状态继续走统一的恢复/重新入场检查。

### 展示与通知

- 页面主表仍可把 `> 200%` 标为埋伏区或高风险。
- 交易条件说明从 `90% < OI/MC <= 200%` 改为 `OI/MC > 90%`。
- 删除“高于 200%，禁止开多”的现行原因文案。为兼容数据库中旧快照，如保留旧原因码映射，文案改为中性的“历史规则：OI / 市值高于 200%”，不得继续表达当前禁止开多。

### 文档

更新 README 和 `docs/2026-09-07-entry-rule-tightening.md`，明确 200% 上限已经撤销，并区分高风险展示与交易准入。

## 测试设计

至少覆盖以下回归场景：

1. 无活动状态、`OI/MC > 200%` 且其他条件全部满足时产生 `LONG`。
2. `no_add`、`OI/MC > 200%` 且恢复条件全部满足时产生 `RESUME_LONG`。
3. 活动 `long`、`OI/MC > 200%` 且无独立停止或退出条件时保持 `long`，不产生 `STOP_LONG`。
4. 活动 `long`、`OI/MC > 200%` 且命中 ATR、移动保护或 EMA 退出条件时仍产生 `EXIT_LONG`。
5. `OI/MC > 200%` 但任一其他入场条件不满足时不得开多。
6. `OI/MC = 90%` 仍被拒绝，`OI/MC > 90%` 可进入后续检查。
7. 前端和企业微信文案不再把 `> 200%` 描述为禁止开多。

## 非目标

- 不让高 OI/MC 绕过技术面、OI 增长、快照完整性或冷却条件。
- 不把 `> 200%` 设为无条件开多或更高优先级信号。
- 不修改 OI/MC 的计算方法、风险分区阈值或主表排序。
- 不修改下单、杠杆和资金管理逻辑。

## 验收标准

- 新增和恢复开多在 `OI/MC > 200%` 时与普通 `> 90%` 候选执行相同条件。
- 高 OI/MC 不再单独产生 `STOP_LONG`、`NO_ADD` 或阻止恢复。
- 独立退出风控行为和故障隔离测试保持通过。
- 后端全量测试、前端测试、Python 编译与生产构建全部通过。
