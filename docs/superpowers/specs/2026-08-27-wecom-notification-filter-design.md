# 企业微信交易通知精简设计

## 目标

企业微信只推送可以做多和必须退出相关信息，不再推送停止做多信息。Web 页面和内部交易状态机继续保留停止做多状态。

## 通知规则

- 保留单币【交易信号：做多】、【交易信号：恢复做多】和【交易信号：必须退出】。
- 不再发送单币【交易信号：停止开多】。
- 【交易条件列表更新】和每小时定时列表只展示“可以做多”和“必须退出”。
- “停止做多”列表发生变化时，不触发企业微信列表更新，也不参与列表通知的去重标识。
- “可以做多”或“必须退出”出现新增币种时，立即推送当前两类完整列表；无新增时继续按一小时周期推送。

## 保留行为

- Web 页面继续展示“停止做多”。
- 停止做多状态继续写入并用于恢复做多、必须退出和冷却判断。
- 数据源异常时继续暂停企业微信交易条件列表推送。

## 实现范围

- 通知发送层跳过 `stop_long` 单币消息。
- 条件列表分发层仅以 `can_long` 和 `exit_long` 判断新增、去重和生成通知。
- 企业微信列表文案删除“停止做多”分组。
- README 同步企业微信通知规则，不修改 Web 页面规则。

## 测试

- 验证 `stop_long` 不调用企业微信单币通知接口，但状态仍正确保存。
- 验证停止做多列表单独变化不会触发列表推送。
- 验证即时列表和每小时列表只包含“可以做多”和“必须退出”。
- 验证可以做多、恢复做多和必须退出通知保持不变。
