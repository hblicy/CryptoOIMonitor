# CoinMarketCap 非法币种隔离设计

## 背景

CoinMarketCap `/v1/cryptocurrency/map` 的 `symbol` 参数只接受逗号分隔的字母数字币种符号。当前程序会把最多 100 个币种放入同一批请求；当其中包含“龙虾”等中文符号，或 CMC 拒绝某个特殊符号时，整批请求返回 HTTP 400，导致 CoinMarketCap 数据源整体异常，并暂停交易条件扫描。

## 目标

- 单个非法币种不得拖垮同批其他正常币种。
- 已配置 `CMC_ID_OVERRIDES` 的中文币种继续直接按 CMC ID 获取市值。
- 没有 ID 映射且不能用于 `symbol` 查询的币种，必须记录明确日志并列为未映射。
- 认证失败、权限失败、限额、服务端错误和网络错误仍使数据源失败，不得静默忽略。

## 设计

1. 在调用 CMC map 接口前，使用 CMC 允许的字母数字规则识别不能作为 `symbol` 参数提交的币种。
2. 对这些币种输出包含币种名称和原因的警告日志，不提交到 map 接口；已有 ID 覆盖的币种不会进入该流程。
3. 对剩余币种维持最多 100 个一批的请求方式。
4. 如果批量请求返回与 `symbol` 校验有关的 HTTP 400：
   - 多币种批次按中点拆成两批并分别重试；
   - 单币种批次仍被拒绝时，记录完整错误并将该币种视为未映射；
   - 其他分批结果继续正常聚合。
5. 非 `symbol` 校验错误不拆分、不忽略，继续向上抛出。

## 可观测性

- 预过滤的非法符号输出警告，并列出币种。
- CMC 单币种拒绝输出警告，包含币种和 CMC 错误信息。
- 不在日志中输出 API Key。

## 测试

- 中文币种与正常币种同批时，正常币种仍能返回市值，中文币种进入未映射列表。
- 已配置中文币种 ID 覆盖时，直接按 ID 获取市值，不调用 map 查询该中文符号。
- CMC 对字母数字币种返回 `symbol` 相关 HTTP 400 时，程序拆分批次并只隔离被拒绝币种。
- HTTP 401、403、429、5xx 以及非 `symbol` HTTP 400 继续抛出。

## 非目标

- 不自动猜测中文币种对应的 CMC ID。
- 不改变 CMC 刷新间隔、交易条件或企业微信推送规则。
- 不修改前端。
