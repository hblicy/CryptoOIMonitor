# 全仓库审计问题修复设计

## 目标

修复本次全仓库审计确认的风控可靠性、刷新资源控制、数据有效性、日志生命周期、配置校验、数据口径和页面提示问题，不改变现有交易策略参数。

## 设计

1. 活跃持仓的移动止盈和强制退出按每根尚未处理的 Binance 已收盘 15m K 线顺序回放。任何历史 K 线触发退出，都先成功发送企业微信，再写入冷却状态；发送失败时保留旧状态，以便下轮重试。
2. 单个币种的回放缺口只生成该币种的可观测失败，不中断其他币种风控。活跃 `long`/`no_add` 状态即使暂时跌出 Binance 成交额币种池也继续使用已持久化的 Binance 交易对执行风控。
3. 手动刷新采用非阻塞互斥和最小时间间隔；正在刷新或距离上次刷新过近时返回 429，不创建等待锁的请求线程。
4. CoinMarketCap 在缓存有效期内即使币种池变化也不刷新报价。已缓存币种继续使用缓存，新币种暂列为未映射，等下一个 CMC 刷新时间统一处理。
5. `ContractOpenInterest`、`MarketCap` 和 `Candle` 在构造时拒绝非有限数、负 OI/成交额及非正价格；快照 JSON 禁止输出 `NaN`/`Infinity`。
6. VPS 日志由 Python `RotatingFileHandler` 管理；启动脚本不再无限追加 stdout。空 CMC Key 启动即失败。
7. OKX 仅聚合 `*-USDT-SWAP`，与其余 CEX 的 USDT 本位口径一致。页面数据源不完整时只展示一条提示。
8. 前端开发依赖升级到不受当前审计漏洞影响、且仍兼容 Node 18/20 的版本。

## 验证

每项先新增失败测试，再做最小实现。最终运行全部 Python 单元测试、Python 编译、Shell 语法检查、前端测试、前端生产构建、`npm audit` 和 `git diff --check`。
